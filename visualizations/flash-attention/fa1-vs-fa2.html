FlashAttention-1 vs FlashAttention-2

The same tiled math on Q, K and V with the loops swapped. FA-1 keeps a K/V tile on chip and sweeps the Q tiles past it. FA-2 keeps a Q tile and its output on chip and streams K/V past it. The full FA-1–4 visualizer goes deeper into each version.

1 · Which matrix sits in the outer loop

Both versions tile S = QKᵀ and never write S to HBM. The center grid is S, one cell per (query tile i, key tile j). Q tiles run down the left, Kᵀ tiles across the top, V tiles across the bottom (Vj pairs with key tile j), and output tiles Oi down the right. The bar inside each O tile shows how many K/V tiles have been folded into it so far. FA-1 sweeps down each column (K/V outer), and FA-2 sweeps along each row (Q outer).

Counts are in tiles (one tile = B × d elements). The scalar statistics m and ℓ (and FA-2's L) are a few floats per row and are left out. FA-2 reads K and V more often than FA-1, but those reads are spread across different thread blocks that all stream the same K/V, so many are served from L2. FA-2's win is not fewer total bytes. It comes from keeping O in registers, from parallelism, and from doing less non-matmul work.



2 · Who does the work: thread blocks on SMs


FA-1 launches one block per (batch, head), and that block walks every tile of the head by itself. FA-2 launches one block per (batch, head, query tile). Toy GPU below: 16 SMs, 8 query tiles × 8 key tiles per head. Change the head count to see when the gap disappears.



  
  
  
  





Real scale, as in the full FA-1–4 visualizer: an H100 has 132 SMs. With batch 1, 32 heads, N = 4096 and 128-row tiles, FA-1 launches 32 blocks (32 of 132 SMs busy) and FA-2 launches 32 × 32 = 1,024 blocks.



3 · Inside one block: how the 4 warps split the S tile


The two versions also cut a single Sij tile in different directions across warps.



  
FA-1: split-K
each warp takes a quarter of the keys in Kj and Vj

    
Each query row is spread across all 4 warps, so each warp holds only a partial max, sum and P·V for that row. At every key tile the warps write their partials to shared memory, wait at __syncthreads(), and read them back to merge.

  
FA-2: split-Q
each warp takes a quarter of the query rows in Qi

    
Each warp owns whole rows. It sees every key for its rows, so its softmax statistics and its rows of O are already complete. Kj and Vj are shared read-only in shared memory, and the warps never exchange partial results.
